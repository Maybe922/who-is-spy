## 游戏功能进展

### 移除 AI 玩家模式

之前尝试过“和 AI 一起玩”的功能，但最后决定不继续保留该方向。今天已经完整删除：

- 单人 AI 模式页面

- AI 相关 API 路由
- AI 客户端封装
- OpenAI / Anthropic SDK 依赖
- 首页里的“单人 vs AI”和“AI 设置”入口

后续 AI 的定位改为“题库生成器”，不参与实时对局。

### 单电脑多标签测试

为了解决只有一台电脑时无法测试多人流程的问题，增加了大厅里的测试入口：

- 每个标签页使用独立的 `sessionStorage` 玩家身份。
- 刷新当前标签页仍可恢复房间。
- 大厅新增“新标签加入测试”入口，可以快速打开新玩家标签。

这样本地一台电脑可以模拟多名玩家。

### 私密词语提示

为了避免玩家在发言或投票时忘词，增加了私密提示：

- 发言阶段显示当前玩家自己的词。
- 投票阶段显示当前玩家自己的词。
- 平票重投阶段也显示当前玩家自己的词。
- 白板不会显示“我的词：白板”，而是显示“我的身份：白板”。

该提示来自服务端已私发给当前客户端的身份数据，不会广播给其他玩家。

### 随机发言顺序

原先发言顺序按进房间顺序排列。今天改成：

- 游戏开始时服务端随机生成一份发言顺序。
- 顺序与身份无关，卧底、白板、平民都一起随机。
- 后续轮次不重新洗牌，只过滤已出局玩家。
- 玩家侧栏仍按原玩家列表展示，发言区使用随机顺序。

## Supabase 接入

今天完成了 Supabase Free 项目创建和数据库连接配置。

当前使用：

- Supabase PostgreSQL
- Region：Northeast Asia (Tokyo)
- `DATABASE_URL`：Transaction pooler，端口 `6543`
- `DIRECT_URL`：Session pooler，端口 `5432`

最终环境变量结构：

```env
DATABASE_URL="...:6543/postgres?pgbouncer=true"
DIRECT_URL="...:5432/postgres"
SESSION_SECRET="..."
```

注意：

- `.env` 已加入 `.gitignore`，不会提交。
- `.env.example` 只保留占位符，不包含真实密码。
- Transaction pooler 需要 `pgbouncer=true`，否则 Prisma runtime 会遇到 prepared statement 冲突。

## 已知注意事项

### 不要在 dev 服务运行时执行 production build

今天遇到过一次页面 CSS 消失的问题。原因是开发服务运行时执行了 `next build`，导致 Next.js 开发态产物被污染。

处理方式：

- 重启 dev 服务即可恢复。
- 后续避免在 `npm run dev` 正在运行时执行 `npm run build`。

### Supabase 密码安全

今天数据库密码曾经出现在聊天里。后续应视为敏感信息处理：

- 不要再把完整连接字符串发出来。
- 不要把 `.env` 提交到仓库。
- 如果担心泄露，应在 Supabase 重置数据库密码。
